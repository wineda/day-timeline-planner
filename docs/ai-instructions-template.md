# AI 指示書の雛形（保管庫側に置くもの）

Day Timeline Planner のノートを AI（Claude など）に読ませるときの指示書の書き方。
**フォーマットの知識は指示書に書かず、プラグインが書き出す仕様書を参照させる**のが要点。
こうしておくと、プラグインの保存形式が変わっても指示書を直す必要がなく、ずれた場合は AI 自身が警告する。

## 準備（保管庫で一度だけ）

1. Obsidian でコマンド「**保存形式の仕様をノートに書き出す（AI 向け）**」を実行する。
   `<フォルダ>/_spec/format.md`（既定 `Timeline/_spec/format.md`）に、この保管庫の設定（フォルダ・見出し・Inbox・チケット管理ツール・メンバー）を埋めた仕様書ができる
2. プラグインを更新したら同じコマンドをもう一度実行する（BRAT で更新したときの手順に入れておく）

## 指示書の雛形

以下を保管庫の指示書（`Rules/…` や `CLAUDE.md` など、今使っている場所）の**フォーマットの説明の代わり**に置く。
業務ルール（何を日報に書くか、どのタグをどう扱うか）は、これとは別に自由に書いてよい。

```markdown
## タスクノートの読み方

- タスクノートの保存形式は `Timeline/_spec/format.md` に書いてある。作業を始める前にまずこれを読むこと
- その文書の `format_version` がこの指示書の想定（**2.1**）と違うときは、作業の最初にそのことを警告し、
  差分に注意して読むこと（フィールドの追加・名前の変更があり得る）
- `format_version` が同じなら、この指示書の残りの部分（業務ルール）に従う
- 集計（予定・実績・差異、タグ別・チケット別）が必要なときは、ノートを自分で集計するより、
  プラグインが書き出した `Timeline/Reports/日報 YYYY-MM-DD.md` があればそれを優先して読む。
  無ければ Obsidian のコマンド「日報（タスクの集計）をノートに書き出す」で作れると案内する
- 本文（備考）の自由記述と `結果` / `原因` / `判断` / `ふりかえり` などの記録欄を混同しない。
  記録欄は「AI が読む欄」として設計されている
```

`format_version` の現在値は `docs/format.md` の frontmatter、またはリポジトリの `app/src/markdown/fields.ts` の `FORMAT_VERSION` を見る。

## 想定している分担

| 何 | どこにある | 誰が更新する |
|---|---|---|
| 保存形式（フィールド・メタ行の文法） | `Timeline/_spec/format.md`（プラグインが生成） | プラグイン。更新のたびにコマンドで書き出す |
| 業務ルール（何をどう記録・集計するか） | 保管庫の指示書 | 人。自由に育てる |
| 実データ | `Timeline/YYYY-MM-DD.md` など | プラグインと人 |
| 集計 | `Timeline/Reports/…` | プラグイン（コマンド） |

## 定期的な突き合わせ（任意）

月に一度、または更新のたびに、AI に次を頼むとずれを早めに拾える:

> `Timeline/_spec/format.md` を読んだうえで、直近 2 週間の `Timeline/*.md` を確認し、
> 仕様に無いラベルの行、別表記のまま残っている行、メタ行の無い見出しでタスクに見えるものを列挙して。直さなくてよい。
