# タスクノートの保存形式

Day Timeline Planner（Obsidian プラグイン）がタスクを保存するときのノートの形と、その読み方。この文書は**プラグインが生成したもの**で、手で直しても次の生成で戻る。AI（日報・振り返り・棚卸しなど）がタスクノートを読むときは、まずこの文書の `format_version` を確認し、指示書の想定と違えば最初に警告すること。

- `format_version` … 保存形式の版。ノートの読み書きの約束が変わったときだけ上がる
- `plugin_version` … この文書を書き出したプラグインの版（UI だけの変更でも上がる）

## ノートの場所

| 何 | 場所 | 中身 |
|---|---|---|
| 日付ノート | `Timeline/YYYY-MM-DD.md` | その日のタスク（この文書の形式） |
| Inbox | `Timeline/Inbox.md` | 日付を決めていないタスク（同じ形式。`登録日` 付き） |
| プロジェクトノート | `Timeline/Projects/<名前>.md` | 大きなタスク。日付ノートのタスクが `プロジェクト` 行でここへリンクする |
| メンバーの予定 | `Timeline/Members/<名前>/YYYY-MM-DD.md`（メンバーごとに設定で変えられる） | 他の人の予定（同じ形式） |
| プラグインの集計 | `Timeline/Reports/日報 YYYY-MM-DD.md`、`Timeline/Reports/予実レポート YYYY-MM-DD.md` | プラグインがタスクを集計して書き出した Markdown。**AI が読む入力として最も扱いやすい**。コマンド「日報（タスクの集計）をノートに書き出す（表示中の日）」「予実レポートを作成（表示中の週）」で書き出したときだけ存在する |
| 日報 | `daily/…YYYY-MM-DD….md` | AI などが書いた日報。プラグインは日付ヘッダーからこれを表示する（設定「日報のフォルダ」） |
| 操作ログ | `Timeline/Log.md` | プラグインがタスクを削除したときの記録（日時・タイトル・元のノート）。「消えたタスク」が意図した削除だったかを確かめるのに使う |

## タスクブロックの構造

タスク1件 = 「見出し + メタ行 + フィールド行 + ステップ + 本文」。ノートのファイル直下（frontmatter の後ろ）に、レベル 2（`##`）の見出しとして並ぶ。

```markdown
## 誤検知の調査 #障害
- [x] 10:00 - 11:00 🎫redmine#65130 🔔10 ^dtp-k3f9a2
- プロジェクト: [[Timeline/Projects/環境構築]]
- 実績: 09:15 - 09:45 / 13:00 - 13:30
- 登録日: 2026-08-10
- 期限: 2026-08-20
- 完了条件: 今日の担当が決まっている
- [x] ログを集める
- [ ] 再現手順を書く
    補足: 手順は Runbook にも転記
- 結果: GenericRFI_BODY の誤検知と特定
- 原因: 署名のパターンが URL エンコード済みの本文に一致
- 判断: 該当ルールを検知モードに落として様子見
- 残: 恒久対応の検討
- 他者: 田中 / ルール変更の承認
- 他者: 佐藤 / 影響範囲の確認
- 回答: 未
- 状態: 中断(承認待ち)
- Owner: 鈴木
- 次アクション: 承認が下りたら本番に反映
- ふりかえり: 調査に時間がかかった

詳細のメモ。ここは自由な Markdown で、プラグインは触らない。
- 箇条書きも書ける
```

上から順に:

1. **見出し行** `## タイトル #タグ` … タイトル。タグは見出しの末尾に 1 つ（`#親/子` の形も）
2. **メタ行** … 見出しの直下の 1 行（空行は挟んでよい）。ここが無い見出しはタスクではない
3. **フィールド行（メタ行の直下）** … `プロジェクト`・`実績`・`持ち越し元`・`持ち越し先`・`登録日`・`期限`・`完了条件`
4. **ステップ** … インデント無しのチェックリスト `- [ ] …`。空行までが 1 つのまとまり。ステップの下のインデント行は補足
5. **フィールド行（ステップの後ろ）** … `結果`・`原因`・`判断`・`残`・`他者`・`回答`・`状態`・`Owner`・`次アクション`・`ふりかえり`
6. **本文（備考）** … 残りの自由な Markdown。プラグインは触らない

### メタ行

```markdown
- [x] 10:00 - 11:00 🎫redmine#65130 🔔10 ^dtp-k3f9a2
```

| 部分 | 意味 |
|---|---|
| `- [ ]` / `- [x]` / `- [>]` | 未完了 / 完了 / **持ち越し済み**（翌日へ送った。完了でも未完了でもない） |
| `10:00 - 11:00` | 予定の時刻（24 時間制）。**無ければ「未スケジュール」**（Inbox や再スケジュール待ち） |
| `🎫redmine#65130` | チケット。`🎫#65130` はツール省略（先頭のツール） |
| `🔔10` / `🔔off` | リマインド（開始 10 分前 / しない）。無ければ既定 |
| `^dtp-xxxxxx` | プラグインが付けるブロックID。`[[Timeline/YYYY-MM-DD#^dtp-xxxxxx]]` で他のノートから参照できる（持ち越しのリンクもこの形） |

手書きで `- 09:00 - 10:00` とだけ書いてもタスクとして認識される（ID は次の保存時に付く）。

### フィールド

本文の `- ラベル: 値` の行。1 行のフィールドは**最初の 1 行だけ**が有効で、2 つ目以降はただの本文。読むときはリスト記号なし・`**ラベル**`・全角コロン・別表記も受け付けるが、プラグインが書くときは下のラベルに統一する。「記録タブ」の欄は、編集画面で作業の記録として「記録」タブに集めているもの（日報・振り返りの元データ）。

| ラベル | 位置 | 値 | 説明 | 実例 | 別表記 | 記録タブ |
|---|---|---|---|---|---|---|
| `プロジェクト` | メタ行の直下 | Wikilink | 大きなタスク（プロジェクトノート）への参照。編集画面の「プロジェクト」欄と相互に反映。手書きの `[[リンク\|別名]]` も読める（ダイアログで変えない限り保持） | `[[Timeline/Projects/環境構築]]` | — | — |
| `実績` | メタ行の直下 | 時刻範囲（`/` 区切りで複数） | 実際に作業した時間。`/` で区切って複数区間を書ける。予定（メタ行）とは独立しているので予実の比較ができる。編集画面の「実績」欄と相互に反映され、空にすると行ごと消える | `09:15 - 09:45 / 13:00 - 13:30` | — | — |
| `持ち越し元` | メタ行の直下 | Wikilink | 前の日から持ち越されたタスクの、元のブロックへのリンク（プラグインが書く） | `[[Timeline/2026-08-18#^dtp-9b2c44]]` | — | — |
| `持ち越し先` | メタ行の直下 | Wikilink | 残件を翌日へ持ち越したとき、続きのブロックへのリンク（プラグインが書く）。持ち越したタスクはチェックが `[>]` になる | `[[Timeline/2026-08-19#^dtp-c0ffee]]` | — | — |
| `登録日` | メタ行の直下 | 日付（YYYY-MM-DD） | Inbox に入れた日（自動で記録）。どれだけ滞留しているかを後から判定できる | `2026-08-10` | — | — |
| `期限` | メタ行の直下 | 日付（YYYY-MM-DD） | いつまでに終えるか（YYYY-MM-DD） | `2026-08-20` | `期日` | ○ |
| `完了条件` | メタ行の直下 | 文字列 | 何ができたら終わりか（ノートに手で書く。編集画面には欄が無い） | `今日の担当が決まっている` | — | ○ |
| `結果` | ステップの後ろ | 文字列 | 何がどこまで終わったかの記録。編集画面の「詳細」にある「結果」欄と相互に反映。日報・週報の元データになる | `GenericRFI_BODY の誤検知と特定` | — | ○ |
| `原因` | ステップの後ろ | 文字列 | 障害・バグ系の記録: 何が原因だったか | `署名のパターンが URL エンコード済みの本文に一致` | — | ○ |
| `判断` | ステップの後ろ | 文字列 | 障害・バグ系の記録: その場でどう判断したか | `該当ルールを検知モードに落として様子見` | — | ○ |
| `残` | ステップの後ろ | 文字列 | 完了にした後に残った作業 | `恒久対応の検討` | — | ○ |
| `他者`（複数行可） | ステップの後ろ | 文字列（複数行可） | ボールが相手にあるものの記録。値は「相手 / 内容」。1タスクに複数行書ける（唯一の複数行フィールド） | `田中 / ルール変更の承認` | — | ○ |
| `回答` | ステップの後ろ | 済 / 未 | 質問への回答が付いたかの記録 | `未` | — | ○ |
| `状態` | ステップの後ろ | 未着手 / 進行中 / 中断 / 回答待ち / 期限未定（中断は `中断(理由)`） | タスクの状態。中断のときは「中断(理由)」のように理由を付ける | `中断(承認待ち)` | — | ○ |
| `Owner` | ステップの後ろ | 文字列 | タスクのオーナー（ボールを持っている人）。「誰の予定か」（どのメンバーのノートにあるか）とは別の記録 | `鈴木` | — | ○ |
| `次アクション` | ステップの後ろ | 文字列 | 未完了事項の次の一手。翌日へ持ち越すと続きのブロックに引き継がれる | `承認が下りたら本番に反映` | — | ○ |
| `ふりかえり` | ステップの後ろ | 文字列 | 作業してみてどうだったか・次はどう改善するか。編集画面の「詳細」にある「ふりかえり」欄と相互に反映 | `調査に時間がかかった` | `振り返り` | ○ |

状態の値: `未着手` / `進行中` / `中断` / `回答待ち` / `期限未定`。中断だけは `中断(理由)` のように理由を付ける。

### 持ち越し

未完了のまま翌日へ送ると、元のブロックはチェックが `[>]` になって `持ち越し先` を持ち、続きのブロックが `持ち越し元` を持つ。

```markdown
## 設計レビューの準備 #開発/設計
- [>] 10:30 - 12:00 ^dtp-9b2c44
- 持ち越し先: [[Timeline/2026-08-19#^dtp-c0ffee]]
- [x] 資料の骨子
- [ ] 図を描く

## 設計レビューの準備 #開発/設計
- [ ] ^dtp-c0ffee
- 持ち越し元: [[Timeline/2026-08-18#^dtp-9b2c44]]
- [ ] 図を描く
```

## 読むときの約束（AI 向け）

- メタ行の無い見出し、コードブロック（```）の中、frontmatter は無視する
- 完了 = `[x]`。`[>]` は持ち越し済み（その日の実績や結果は残っていることがある）。`[ ]` で時刻が無いものは未スケジュール
- 「今日やった」は `結果` と `実績` で判断する。`完了条件` は予定側の記述
- `他者` は複数行あり得る。`相手 / 内容` で分ける
- `状態: 中断(理由)` の理由、`回答: 未` の質問、`期限` を過ぎた未完了は、日報で拾う候補
- `登録日` は Inbox に入れた日。滞留日数の計算に使う
- 集計が目的なら、プラグインが書き出す `Reports/日報 …` の表を読む方が確実（同じデータから生成している）

## 手で書くときの約束

- 新しいタスクは「見出し + メタ行」だけで足りる。ID はプラグインが次に保存するときに付ける
- フィールドは上の表のラベルで書く（別表記は読めるが、保存時に統一される）
- プラグインの書き込みはブロック単位の部分置換で、本文や並び順は勝手に変えない
